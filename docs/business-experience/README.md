# رؤية منصة الإقامة الذكية — تجربة تحليل الأعمال التفاعلية

عرض تفاعلي موجّه للعميل يحوّل الفكرة الأولية لمنصة حجز وإقامة ذكية (شقق، فنادق، وحدات سكنية) إلى رؤية منتج منظّمة:
الحجز، والدخول الذكي، والتشغيل والإشراف، والتسعير الذكي، والمساعد الشخصي، ومؤشرات الأداء، والحملات، وتكاملات الامتثال (شموس، نفاذ، إيواء).

> **مهم:** هذا **مفهوم أولي للنقاش** وليس مواصفات نهائية. كل عنصر في العرض موسوم بحالته، وجميع الواجهات والمؤشرات والأمثلة توضيحية ولا تحتوي أرقاماً أو أسعاراً فعلية.

---

## التشغيل

افتح `index.html` مباشرة في المتصفح (Chrome أو Edge أو Safari أو Firefox حديث). لا يحتاج خادماً ولا خطوة بناء.

- يتطلب **اتصالاً بالإنترنت** لتحميل الخطوط والمكتبات من CDN.
- للعرض دون إنترنت: نزّل المكتبات الأربع أدناه إلى `assets/` وعدّل روابط `<script>` في نهاية `index.html`.

## وضع العرض (للاجتماعات)

| الإجراء | المفتاح |
|---|---|
| الدخول إلى وضع العرض | زر «وضع العرض» أو المفتاح `P` |
| القسم التالي | `→` (السهم الأيمن) أو `PageDown` |
| القسم السابق | `←` (السهم الأيسر) أو `PageUp` |
| القسم الأول / الأخير | `Home` / `End` |
| الخروج | `Esc` |

يعرض كل قسم كشريحة ملء الشاشة مع مؤشر القسم وشريط التقدّم. إن رفض المتصفح ملء الشاشة (مثلاً داخل إطار مضمَّن)، يعمل الوضع داخل الصفحة بالمفاتيح نفسها.

### المشاهد ثلاثية الأبعاد (Three.js)

1. **منظومة العقارات** (البداية): نواة المنصة وحولها فنادق وشقق ووحدات سكنية متصلة بتدفقات بيانات.
2. **دورة حياة العقار**: حلقة من 11 مرحلة يتنقّل عليها العقار، قابلة للنقر.
3. **الدخول الذكي**: طبقة رقمية (الحجز ← رمز الدخول) فوق طبقة مادية (العميل ← القفل ← العقار)، متزامنة مع خطوات القسم.
4. **خريطة الطلب للتسعير**: تقويم خمسة أسابيع يتفاعل مع إشارات الطلب (محاكاة مفاهيمية).
5. **منظومة التكامل**: المنصة وشموس ونفاذ وإيواء؛ الخطوط المتقطعة تعني تفاصيل لم تُؤكَّد.
6. **منظومة المنتج**: 12 عنصراً حول النواة، مع تمرير المؤشر للتفاصيل والسحب للتدوير.

كل مشهد لا يُرسَم إلا عند ظهوره على الشاشة، ويُبطَّأ عند تفعيل «تقليل الحركة» في النظام.

## تعديل المحتوى

البيانات المنظّمة في أعلى `script.js` ويمكن تعديلها دون لمس المنطق:

| الثابت | المحتوى |
|---|---|
| `ROLES` | الأدوار السبعة |
| `GUEST` | مراحل رحلة الضيف |
| `LIFECYCLE` | مراحل دورة حياة العقار |
| `ASSIST` | قدرات المساعد والمحادثات التوضيحية |
| `COMPLIANCE` | بطاقات شموس ونفاذ وإيواء |
| `ECO` / `ECO_LINKS` | عناصر منظومة المنتج وروابطها |
| `DATAFLOW` | محطات تدفق البيانات |
| `REQS` | المتطلبات الوظيفية (59) — الترقيم `FR-xxx` تلقائي |
| `RULES` | قواعد الأعمال (18) — الترقيم `BR-xxx` تلقائي |
| `SCOPE` | مناطق النطاق الثلاث والتطويرات المستقبلية |
| `QUESTIONS` | الأسئلة المفتوحة (33)؛ السؤال المحاط بمصفوفة `['…']` موسوم «أضافه الفريق» |

الإحصاءات في الملخص التنفيذي تُحتسب تلقائياً من هذه البيانات.

علامات «تمت مناقشته» في قسم الأسئلة المفتوحة تُحفظ في متصفح العارض فقط (`localStorage`) ولا تُشارَك مع غيره.

## ما لا يدّعيه هذا العرض

- لا يحدد مزوّد قفل ذكي أو واجهة برمجية أو بروتوكولاً.
- لا يحدد مزوّد دفع أو طرق دفع.
- لا يحدد نموذج ذكاء اصطناعي أو خوارزمية تسعير أو مصدر بيانات.
- لا يحدد مواصفات تكامل شموس أو نفاذ أو إيواء؛ الغرض المعروض «متوقع» وبانتظار التأكيد، وطبيعة «إيواء» تحديداً تحتاج تأكيد الجهة المقصودة.
- لا يحدد مبالغ غرامات أو صياغة قانونية أو آلية تحصيل أو قرارات مسؤولية.
- لا يمثل التطوّر المقترح جدولاً زمنياً متفقاً عليه.
